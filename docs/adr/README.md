# ADR — Architecture Decision Records

本目录记录对本项目有长期影响的架构 / 工程决策。每条记录回答四个问题：**背景**（为什么现在要定）、**决定**（选了什么）、**后果**（代价与收益）、**被替代的旧决定**（如果本次推翻 / 取代了之前某个决定，把它记下来，防止后人分不清哪个是当前契约）。

写新决策时：拷贝 `template.md`，编号递增（`0005-...`），标题用 kebab-case，尽量简洁、基于**实际实现**而不是愿望。

## 约定

- 每条记录必须写明「被替代的旧决定」；本次全新决策则写「无」。
- 记录的是**当前事实**；一旦实现偏离，先改 ADR 再改代码，或反过来但同步更新。
- PR 模板含「本次是否改变了上述契约」勾选项；改动生命周期 / ABI 类契约必须联动本目录。
